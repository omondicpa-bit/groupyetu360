# GroupYetu360 codebase audit, 4 October 2026

Scope: the web app (index.html, style.css, js/*.js, sw.js), the Supabase
Edge Functions, the SQL migrations in the repo and the Android build. The
database's live access rules (RLS) could not be read from the repo; a
read-only query is provided to complete that part.

## Fixed in this delivery

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | Stored XSS: about 90 places put member-entered text (names, notes, notices, meeting venues and agendas, welfare and fund names, activity log names) into the page without escaping. A member could register a name containing script that runs in an admin's browser. | Wrapped in `h()`; 77 found automatically, the rest by hand. |
| 2 | High | Inline handler arguments built as `'${name.replace(/'/g,"&apos;")}'`. `&apos;` turns back into `'` inside the attribute, so a name could end the string and run code. | New `jsArg()` (JSON-quoted and HTML-escaped) used for every such argument (21 places). |
| 3 | Medium | Two-factor codes could be guessed: no limit on wrong attempts. | `verify-2fa-otp` burns a code after 5 wrong tries (`otp_attempts_2026-10-04.sql`). |
| 4 | Medium | Superadmin "Onboard group" button called `saveOrg()`, which did not exist. | `saveOrg()` added. |

## Open, in order of priority

1. **Members can write group records (High, open since 1 Oct).** RLS on `members`, `transactions` and `payment_requests` gives every member write access. Run `audit_rls_readonly_2026-10-04.sql` (read only) and send the result; the fix is role-aware policies using `user_orgs.role`, tested locally first.
2. **Two-factor sign-in is enforced only in the browser (High).** The password alone creates a valid session; the app signs out and waits for the code, but someone calling Supabase directly with a stolen password skips the code. Proper fix: Supabase's built-in MFA (TOTP or phone), with RLS requiring assurance level `aal2` for admin, treasurer and superadmin.
3. **Android signing keystore committed publicly (High).** `keystore-base64.txt` is still in the repo (the build now uses a GitHub secret). Delete the file and its history, and ask Google Play for an upload-key reset; Play App Signing protects the app's real key.
4. **Admins can change their own plan and SMS bundle (Medium, open since 1 Oct).** Plan activation runs in the browser. Move it to a server function or a database guard like the instant-pay switch.
5. **Supabase library loaded unpinned from a CDN (Low).** `@supabase/supabase-js@2` follows every new release. Pin an exact version, and add a Subresource Integrity hash.
6. **Backup payment providers (Low).** SasaPay and Paystack functions and UI remain as backup. Undeploy the Edge Functions that are not in use to reduce what is exposed; keep the code.

## Housekeeping

- `style.css` is 4,100 lines with layered overrides from each redesign phase. Consolidate once the UI settles.
- One-off SQL files sit in the repo root. Move them to a `sql/` folder with a short log of when each ran.
- Functions allow any origin (CORS `*`); acceptable because every call needs a token, but worth narrowing to the app's domains.
